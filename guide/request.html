신청과 승인

예약 신청 한 건이 이용자 화면에서 사장님 화면으로 넘어가고, 승인·거절·만료로 끝나기까지 데이터가 어떻게 바뀌는지 설명해요.

상태의 흐름

지금 오운디는 앱에서 돈을 받지 않는 승인제예요. 신청하면 REQUESTED(승인 대기), 사장님이 승인하면 CONFIRMED(예약 확정), 거절하면 REJECTED, 승인 마감이 지나면 EXPIRED가 돼요.

승인 대기는 자리를 차지하지 않아요. 그래서 같은 시간에 여러 팀이 신청할 수 있고, 사장님은 신청 순서를 보고 정해요. 순서는 보여 주기 위한 것이지, 먼저 신청한 팀이 자동으로 승인되는 건 아니에요.

신청 한 번의 처리 순서

  1. 로그인한 이용자, 슬롯, 중복 방지 키, 인원, 화면에 보였던 가격을 확인해요.
  2. 같은 키로 이미 신청했다면 기존 결과를 돌려줘요. 키는 같은데 슬롯이나 인원이 다르면 거절해요.
  3. 시설·공간·시간·가격·정원을 서버에서 다시 읽어요. 화면에 보였던 가격만 믿지 않고, 그새 가격이 바뀌었으면 다시 확인하도록 해요.
  4. 현재 가격 버전으로 금액을 계산해요. 1회 대관가면 그 금액, 1인 가격이면 단가×인원이에요.
  5. 승인 마감을 ‘이용 시작 + 30분’으로 정해 저장하고, 같은 트랜잭션에서 그 시설 사장님들에게 알림을 만들어요.

예약에는 신청 당시의 가격 ID, 금액, 시작 시각, 취소 규정 버전, 어느 검색에서 왔는지(검색 실행 ID)를 함께 고정해요. 나중에 가격이 바뀌어도 과거 예약을 오늘 가격으로 다시 계산하지 않아요.

승인할 때 일어나는 일

사장님 권한(시설 멤버십) → 아직 승인 대기인지 → 마감 전인지 → 슬롯·공간·시설 상태 → 이미 확정된 예약과 정원 순서로 확인해요. 승인과 동시에 같은 시간의 다른 신청을 정리하는 일까지 한 트랜잭션에서 처리해요.

  • 1회 대관: 한 팀을 승인하면 같은 시간의 나머지 신청은 모두 자동 거절돼요.
  • 1인 가격: 승인 뒤 남은 정원보다 인원이 많은 신청만 자동 거절되고, 남은 정원 안의 신청은 그대로 기다려요.

상태를 바꿀 때는 ‘지금 승인 대기인 경우에만’이라는 조건을 붙여요. 두 사람이 거의 동시에 처리해도 이미 바뀐 상태를 덮어쓰지 않아요.

시간 경계

  • 승인 마감은 시작 + 30분이에요. 그 시각부터는 승인할 수 없어요.
  • 이용자 취소는 시작 30분 전보다 이른 시각까지만 돼요. 딱 30분 전부터는 앱에서 취소할 수 없어요.
  • 사장님은 시작 전까지 취소할 수 있어요.
  • 이용자가 시간을 바꾸려면 취소 후 다시 신청해요. 사장님은 시작 전에 같은 종목·같은 금액의 빈 시간으로 옮길 수 있고, 옮기기 전후 기록이 남아요.

함께 바뀌거나, 함께 취소돼요

예약 상태와 알림은 같은 데이터베이스 트랜잭션으로 묶여 있어요. 승인 도중 알림 저장이 실패하면 예약도 승인 전 상태로 돌아가요. ‘예약은 확정됐는데 알림은 없는’ 반쪽 상태가 생기지 않아요.

쓰기 트랜잭션은 시작할 때 공용 버전 행을 잠가서, 서버가 여러 대여도 쓰기가 차례로 처리돼요. 승인 경쟁이나 정원 계산을 단순하고 안전하게 만드는 대신, 쓰기가 많아지면 대기가 생길 수 있어 앞으로 측정하며 나눌 계획이에요.
